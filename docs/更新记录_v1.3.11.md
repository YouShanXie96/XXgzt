# 更新记录 v1.3.11（2026-11-18）

仍是同一个文件：`src/selectionpool/driver-v2.js`（上一版备份 `driver-v2.js.bak-20261117-184254`）。

这一轮是修 v1.3.10 上线后那次上架暴露出来的三个问题。

---

## 1. 上架在提交前被自己拦住：「页面自检无返回」

`[dialog-guard] 上架中断：关键字段校验未通过……页面自检无返回`

上一轮把 `preSubmitCheckScript` 里的样品判定换成 `xhSampleRead()` 时，删掉了 `radioState`，
但脚本末尾的返回对象还写着 `sampleRadio:radioState` → **ReferenceError → 整个脚本抛错**，
主进程 `JSON.parse('null')` 得到 `pre=null`，于是「页面自检无返回」直接中断。

- 修：返回对象改成 `sampleRadio:sampleRead`；
- 新增自测 `driver-runtime-check.js`：用空 DOM 把 `preSubmitCheckScript` 真跑一遍，必须返回 JSON。
  以后再有同类「脚本里引用了不存在的变量」，本地就能抓到，不会等到上架现场。

## 2. 素材中心根本打不开（`no-media-frame`）→ 图只能靠直写地址

v1.3.10 用 `buildOpenImageEntryScript` 里的 `element.click()`（**合成** click）去点空图位。
真实页面不吃合成点击：点完什么都没发生，既没有素材中心 iframe，也没有文件输入框，
日志就是 `素材中心未通过（no-media-frame）` → 选择框也 `no-file-chooser` → 最后只能写 URL。

- 老软件是 `realClickAt(dbg, slotSelector)`：**CDP 真实鼠标**点图位（`form-capture-publish-images.js:fillMainImage`）。
- 现在：`buildImageEntryPointsScript` 把这一组的候选点全找出来（`.empty-container`、`上传图片` 按钮…），
  `openMediaDrawer` 逐个用 CDP 真实鼠标点，直到素材中心弹出来；点击期间同时开
  `Page.setInterceptFileChooserDialog`，万一这个图位是「直接挂本地上传」型，文件直接喂给它，不会弹原生框。

## 3. 是否为样品：找到了真实数据键的方向

本轮日志 `[fill-extra] 是否为样品=正装（已回读）` 后面没有任何模型信息，说明按 label 在
`itemProp/keyProp/bindProp` 里**没找到**「是否为样品」这条属性 —— 它不是类目属性。

老软件 `form-capture-harvest.js` 取的是 `keep.sampleItem`，而 `keep` 是
**`window.Json.models.formValues` 的顶层键深拷贝** —— 即 `formValues.sampleItem`，值 0=正装 / 1=样品。

- 现在三路一起写：① 按「选项里同时有 正装/样品」识别的类目属性（`{value,text}`）；
  ② `sampleItem` 组件/fomValues 顶层键（按它当前的值形状写 `0` 或 `{value:0,text:'正装'}` + `setProps`）；
  ③ DOM 单选框点击兜底。
- 判定仍是「模型 + radio」双确认；失败时日志会多打一段**候选**，直接把 formValues 里谁的值是「正装/样品」列出来：
  `[fill-extra] 是否为样品=样品（⚠ 仍是样品，请手动选正装（候选 sampleItem:样品））`
  下次只要看这一行，就能确定真实键名，不必再猜。

## 4. 透明素材图：改成真上传 800×800（老软件同款）

### 老软件怎么传的

`form-capture-publish-images.js:fillGuideWhiteBgImage`

1. 读 `#struct-whiteBgImage .empty-container`，不可见就直接放弃（提示人工上传）；
2. `realClickAt` 真实鼠标点这个空图位 → 弹出素材中心；
3. `fillMainImage({ slotSelector:'#struct-whiteBgImage .empty-container', forceExactPx:800 })`：
   - 页面内 fetch 主图 → canvas **强制画成 800×800 的 PNG** 落到本地临时目录；
   - 素材中心「本地上传」→ 用 DataTransfer 把这张 PNG 塞进 `input[type=file]`（不走原生文件框）；
   - 上传面板里按文件名确认「上传成功」→ 点「完成」；
   - 在 iframe 里勾选这张卡片，再用父页 CDP 坐标点一下图（穿透 OOPIF，触发实时回填）；
   - 裁剪框点「确定」（800×800 固定），父页抽屉底部再点「确定」；
   - 以 `#struct-whiteBgImage` 里有图为准。

### 我们之前怎么传的

`uploadWhiteBg` 顺序是：真实点图位试原生选择框 → 本地上传框 → 素材中心 → 整组串行 → **最后直接写 CDN 地址**。
透明素材图这个图位点完什么都不弹（第 13 轮现场：`fileInputs:0`、无 iframe），前四条全落空，
就走到「直接写 `guideImageGroup.whiteBgImage = 主图_800x800.jpg`」——
主图不是正方形时 `_800x800` 只是「等比缩到 800 以内」，出来可能是 750×800，
平台就标红「图片像素必须是800\*800，请修改！」，这张图也就等于废的。

### 现在怎么传

- 顺序改成：**素材中心真实上传（800×800 PNG）→ 原生选择框 → 本地上传框 → 整组串行 → CDN 直写兜底**；
- 上传用的就是 `buildMakeSquarePngScript` 生成的**精确 800×800 PNG**（透明底、等比居中），和老软件 `forceExactPx:800` 一致；
- 直写兜底仍然保留，但只有候选图**真的是 800×800** 才写，否则不写（写进去只会标红并挡提交，日志会报 `size-not-800` 和实际尺寸）。
