# 更新记录 v1.3.3（2026-11-12）· 双击 exe 打不开

## 现象

双击 `谢谢工作台.exe` 没有任何反应（不弹窗、不报错、任务栏也没图标）。

## 根因：进程还在跑，但已经没有窗口了 —— 它一直占着「单实例锁」

现场证据（我在这台机器上抓的）：

- 任务管理器里 `谢谢工作台.exe` 有 8 个进程，主进程从 09:07 就在，**但枚举窗口只有**
  一个隐藏的「商家中心－宝贝管理」（店铺浏览器），**没有 `谢谢工作台` 主窗口**；
- 再双击 exe 时，Electron 走 `app.requestSingleInstanceLock()` 判定「已经有一个实例」→ 直接 `app.quit()`，
  而旧实例的 `second-instance` 回调里 `mainWindow` 已经没了 → 什么都不做 → 用户看到的就是「双击没反应」。

主窗口没了进程却还在，卡在退出流程上：

1. 用户点 × → `mainWindow.on('closed')` → `app.quit()`；
2. `before-quit` 拦住，跑 `finishShutdown()`：停服务 → `selectionpool.dispose()` → `stopIngestServer()`；
3. 旧实现是 `server.close(cb)`，**它只等连接自然结束**；插件/浏览器留着 keep-alive 连接时不回调 →
   退出流程永远悬着 → 进程活着、没有窗口、锁不放。

## 改了什么

| 位置 | 改动 |
| --- | --- |
| `selectionpool/service.js` `stopIngestServer` | `server.closeAllConnections()` 主动断开，`close` 再加 2 秒兜底超时；不会再卡住退出 |
| `src/main.js` `before-quit` | 退出流程加**硬上限 6 秒**：`Promise.race(finishShutdown, 6s)` 后一律 `app.exit(0)`；异常写 `用户数据/shutdown-error.log`，不再弹「退出时保存失败」把退出也拦住 |
| `src/main.js` `second-instance` | 老窗口还在 → 还原/显示/聚焦（原逻辑）；**窗口已不存在 → `app.relaunch()` 后退出**，下次双击一定能把界面拉起来 |
| `src/main.js` `ready-to-show` | 增加 `did-finish-load` 后 8 秒兜底显示：万一首帧没画出来也不会「在跑但看不见」 |
| `src/main.js` 启动末尾 | 15 秒看门狗：没有可见主窗口就强制显示；连窗口都没了就退出，避免再留下僵尸进程 |

## 验证（本机实测）

```
① 启动：进程 29952 起来，可见窗口「谢谢工作台」，渲染层无任何 console 错误，上品库列表 25 行正常
② 关闭：点窗口 × → 1 秒内进程全部退出（exitCode=0），任务管理器无残留
③ 再双击：第二实例立刻退出，主进程仍是原来那一个，窗口保持可见（单实例 + 聚焦正常）
④ CDP 检查：v1.3.3 渲染层模块齐全（XHSelectionPool / Dialogs / Editor / PluginManager），0 异常
```

## 你这边要做的

1. 现在这个实例是我刚起的（窗口应该已经在你屏幕上）；
2. 如果以后又遇到「双击没反应」，先看任务管理器有没有 `谢谢工作台.exe` 残留 —— 这次之后它会在 6 秒内自己退干净；
3. 版本显示 **v1.3.3**。

> 附注：如果你从某些开发工具（例如设置了 `ELECTRON_RUN_AS_NODE=1` 的终端）里启动这个 exe，
> 它会以 Node 模式直接退出、不显示界面——那是环境变量导致的，双击（资源管理器）不受影响。
