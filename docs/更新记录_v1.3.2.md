## 三、上架填不进去（你那份日志：属性 0/20、SKU 0/10、主图回读 0 张、最后 `"[object Object]" is not valid JSON`）

四个真原因，全部已修（工作台 1.3.2）：

1. **直接崩在提交前**：`probeScript()` 返回的是对象，代码又对它 `JSON.parse` → 抛 `"[object Object]" is not valid JSON`。
   这就是日志里那一行失败的原因（填完图片后整个流程被这个异常终止）。→ 改成直接用对象。
2. **表单还没渲染完就开始填**：只等标题出现（2s）就往下走，而属性/SKU/图片模块是异步挂载的。
   → 现在等「表单项 ≥ 6 且数量连续两次不变」（最多 90s），日志打印 `表单项=N 上传框=N engine=yes/no`；表单项偏少时明确告警。
3. **SKU 价格行根本不存在**：发布页要先选「销售属性（规格值）」才会生成 SKU 行，我们之前直接去填价格 → 必然 0/10。
   → 新增 `selectSkuSpecsScript()`：按采集到的 `sku_properties`（规格名 + 规格值）在发布页逐个选中，再填价格/库存；日志 `[fill-sku] 规格值：已选 N 个`。
4. **字段可能在同源 iframe 里**：只在顶层 `document` 查，父页面查不到就全空。
   → 新增 `xhDocs()/xhAll()`，属性、SKU、必填兜底、组件填充、规格值选择都跨同源 iframe 查找。

另外 SKU 行匹配改成「忽略 emoji/【】/空格 后再比前 10 字」，带 ✅【…】的规格名也能对上。
