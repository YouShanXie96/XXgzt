## 1. 打开选品太慢（截图 1「未命名商品 · 正在读取选品内容…」）

**根因**：`service.editorLoad` 把 6 件事**串行** await：
`repo.detail`（读 228KB items.json）→ `editorStore.ensure`（读 189KB editor-drafts.json）
→ `shopSession.listShopStates`（可能探会话）→ `editorBackfillTargets`（**又把上面两个文件各读一遍**）
→ `drawingClient.readiness` → `buildThumbnails` → `categoryService.lookup`。
弹窗标题也要等数据，所以在读出标题前一直显示「未命名商品」。

**改了什么**

| 位置 | 改动 |
| --- | --- |
| `selectionpool/service.js` | 详情只读一次、草稿复用给 `editorBackfillTargets`；店铺状态 / 入仓记录 / 作图服务 / 类目反查 / 预览图 / 缩略图**全部并行**；没有本机成品时不再白读盘 |
| `selectionpool/service.js` | 新增 `resolveCategory()` + 叶子类目路径缓存（同一个类目只查一次类目树） |
| `renderer/selectionpool/editor.js` | `load(itemId, row)` 接收列表行，**先画外壳再读数据**；新增骨架屏（`skeleton()`），不再是一片空白 |

**怎么验**：点「图片」或整行，标题/平台/商品ID/店铺/价格立刻出现，骨架屏 1 帧内换成真实内容；
本机实测 `editorLoad` **21ms**（同一条选品 #25，见下方冒烟测试）。

## 2. 视频要先把鼠标移到视频上才采得到

**根因**：新版商品页的视频播放器是**懒挂载**（hover / 进视口才请求），点采集时 `<video>` 还不存在；
`page-hook` 又只保留最近 6 条 mtop 响应，视频那条（pcdetail）早被别的响应挤掉了。

**改了什么**

| 文件 | 改动 |
| --- | --- |
| `extension/src/page-hook.js` | 按接口种类分桶保留（pcdetail / getdetail / getdesc 各 8 条，总 24 条），同 URL 轮询只留最新；**永不先丢 pcdetail/getdetail/getdesc** |
| `extension/src/capture.mjs` | 新增 `nudgeVideoLoad()`：滚到视频区 + 派发 `pointerover/mouseover/mouseenter`，让播放器挂出来；已有 `<video src>` 时零成本 |
| `extension/src/capture.mjs` | `collectVideos()` 增加 `data-video-url/data-play-url/data-mp4`、`__INITIAL_STATE__` 一类全局对象、更多内嵌键 |
| `extension/src/page-data.mjs` | 视频键扩到 `videoList/videoInfo/videoUrls/playUrl`，并**兜底扫描任意字段里的 mp4/m3u8 直链** |
| `extension/content.js` | 采集前先 `nudgeVideoLoad()`，再问钩子；没采到就再采一次 DOM + 重新问钩子 |
| `extension/background.js` | 视频为空时补一次**手机端视图** getdetail（`preferWireless`），取 `item.videos / item.videoUrl` |

**怎么验**：刷新商品页 → 不碰鼠标直接点「加入上品库」→ 提示条 `视频 1`；工作台「视频」页签能看到封面与「打开」。

## 3. 上架进度跑到顶部横条，上架记录里看不到

**根因**：`service.autoShelf` 用 `progress()` 往 `state.progress['selectionpool:']` 写，于是顶部出现
「上品库 · [1/1] 正在处理选品 #25」横条（截图 2 红框）；队列弹窗只拿到总进度，没有「正在上架 / 排队中」的逐件状态。

**改了什么**

| 位置 | 改动 |
| --- | --- |
| `renderer/app.js` | 上品库进度**不再写顶部横条**（`stage=queue/log` 直接 return，其余只处理一次性通知与列表刷新） |
| `selectionpool/service.js` | 队列增加逐件状态 `items[]`：`queued / running / done / failed / stopped`，每件带标题、店铺、开始/结束时间 |
| `selectionpool/repository.js` | `setQueueState` 落盘 `items`（之前只存 8 个计数 + 日志，所以重开弹窗就丢） |
| `renderer/selectionpool/dialogs.js` | 队列弹窗新增**队列板**：正在上架 / 排队中 / 已入仓 / 失败·未执行；日志区加「完整日志 / 看全部（600 行）/ 复制全部」，自动滚到底且不再抢输入焦点 |
| `renderer/selectionpool/dialogs.js` | 修 `dlg-shelf-shopcat` 之前没有处理分支（选完店铺分类不保存） |

**怎么验**：勾选几件 → 自动上架 → 顶部**不再出现横条**；「查看上架进度 / 上架日志」弹窗里能同时看到
正在上架的那件（带用时）和排队中的剩下几件，日志逐行滚动。

## 4. 编辑器弹窗点 × 关不掉

**根因**：`case 'close'` 里 `if (ui.dirty) { const go = await modal(...) }`。
而 `app.js` 的 `modal()` 有 `if (modalInFlight || dialog.open) return null;` —— 只要之前有任何一次
原生 `<dialog>` 没被关干净，这里就**静默拿到 null 并 return**，于是 × 看起来完全没反应。

**改了什么**

- 关闭不再走二次确认：草稿本来就是**每次改动自动落盘**的，直接关；
- 同时补 `Esc` 关闭（先关图片全貌 → 再收换图菜单 → 最后关弹窗）；
- `dialogs.js` 的「商品图片工作台」入口改用 `window.XHSelectionPoolEditorApi`（之前取的是不存在的 `.instance`）。

**怎么验**：点 ×、按 Esc、「稍后」都能立刻关；重开还在原来的编辑内容上。

## 5. 弹窗里滚轮把外面整页也滚走

**根因**：弹窗内滚动容器滚到底后，滚轮事件继续冒泡给 `#content`，整页跟着跑（截图 4）。

**改了什么**

- CSS：`.sped-scrim / .spx-backdrop / .sp-dialog-backdrop` 及所有内部滚动容器加 `overscroll-behavior: contain`；
- `editor.js` 新增 `installGuards()`：滚轮落在弹窗里时，**到边界就 `preventDefault()`**；落在弹窗空白处也吃掉，不传外层。

**怎么验**：把 SKU 规格列表滚到底继续滚，后面的上品库列表不动；鼠标停在弹窗头部滚动也不会带动整页。

## 6. 图片不能替换 / 不能拖动 / 不能单张换编码

**根因**：`orders` 与 `replaced` 两套映射**只存不画**（`squareSection` 根本没读），也没有任何拖动逻辑；
`editorReplaceImage` 只接受 https，`local:` 还被 `SKU_IMAGE_SOURCE` 正则挡掉。

**改了什么**

| 位置 | 改动 |
| --- | --- |
| `selectionpool/editor-store.js` | 新增草稿字段 `slotImages[group] = [图, …]`（1:1 / 采集原图 / 3:4 各 5 位，**按下标保留位置**）；`SKU_IMAGE_SOURCE` 支持 `local:<绝对路径>.jpg|png|webp` |
| `selectionpool/service.js` | `editorReplaceImage` 支持三种来源：`code`（AI作图编码取第 N 张）、`local`（本机图片）、`src`（https），并**按图位下标**写入 `slotImages`；`clear` 还原成采集原图那一张 |
| `selectionpool/service.js` | 新增 `editorPickImage`：弹文件选择框 → 复制进 `用户数据/selectionpool/media/`（内容哈希命名）→ 生成 data URL 预览 |
| `selectionpool/service.js` | `replacedPreviews()` 按**原值**（`local:…`）生成预览，拖动换位后预览仍跟着那张图 |
| `renderer/selectionpool/editor.js` | 图位卡片支持 `draggable` 拖动排序（`moveSlot` → 写 `slotImages`）、拖放高亮、左上角拖动把手；「换图」菜单四项：换编码的图 / 用本机图片 / 填图片地址 / 还原这张 |
| `renderer/selectionpool/selectionpool.css` | `.sped-slot-menu / .sped-slot-drag / .sped-slot-dragging / .sped-slot-over` 等样式 |

**怎么验**：1:1 主图 → 拖动第 1 张到第 2 位（松手即落盘）→ 点某张「换图 → 换编码的图」→ 填编码回车，
该图位换成作图成品；「还原这张」回到采集原图。

## 7. 1:1 主图获取不到（老软件读的是手机端 1:1）

**根因**（两层）：

1. **插件侧**：新版页面主图位展示的是 3:4 竖图，`item.images`（手机端 1:1 原图）只在接口里，
   而 getdetail 走的是 PC 视图；
2. **工作台侧**：编辑器把 1:1 那一栏固定画成「作图成品」的 5 个空位，采集原图被折叠在下面，
   所以**看起来永远是空的**。

**改了什么**

| 位置 | 改动 |
| --- | --- |
| `extension/src/mtop.mjs` | `createMtopDetailData/buildMtopDetailUrl` 支持 `preferWireless`（`exParams.preferWireless=true` + `channel=h5` + `ttid`），`extractMobileDetailMainImages` 兼容 `item.images / item.item.images / data.images` 与对象条目 |
| `extension/background.js` | `fetchAllDetailData` 在「1:1 主图不足 3 张」或「没有视频」时补一次手机端视图请求并合并 |
| `renderer/selectionpool/editor.js` | 1:1 主图改成**一组图位 + 来源切换**（作图成品 / 采集原图）：没有作图成品时自动用采集原图，5 个图位不再空着 |

**怎么验**：重新「加入上品库」一条商品（插件 0.6.19）→ 工作台「1:1 主图」直接显示手机端方图；
点「作图成品」若没有成品会提示先填编码。

## 8. 行里空白位置点不动

**根因**：表格行没有点击动作，只有右侧「图片 / 详情」等链接可点。

**改了什么**

- `listView()` 的 `<tr>` 加 `data-action="selectionpool:images" data-id`：**整行任意空白处都打开商品图片工作台**；
- 勾选框改成独立动作 `selectionpool:toggle-select`（不会误触打开弹窗）；
- CSS `.sp-row` 悬停高亮 + 指针。

**怎么验**：点商品名、加入时间、作图图片、流程、分组、归属任意空白处 → 打开同一套工作台。

## 9. 「详情」要像老软件那样显示采集信息

**根因**：`详情` 和 `图片` 都打开同一个编辑器，没有采集信息页。

**改了什么**

- `dialogs.js` 新增**采集信息弹窗**（复刻老软件截图 6）：标题栏（平台 / 商品ID / 归属 / 加入时间 / 打开原页面 / 商品图片工作台 / ×）
  + 六个页签：**概览 / SKU / 商品参数 / 图文详情 / 评价 / 采集信息**；
- 概览：左侧大图 + 缩略图切换，右侧 店铺 / 采集价 / 原价 / 促销价 / 品牌 / 类目路径 / 类目ID / 采集时间 / 副标题 / 服务承诺，
  下方四张卡：销量与评价 / 店铺信息 / 物流 / 主图视频；
- 缺失项统一显示 `未采集`，不编造数值（与老软件一致）。

**怎么验**：点任意「详情」→ 看到采集信息而不是编辑器；切页签能看到 SKU 表、参数、详情长图、评价。

## 10. 上架流程按老软件日志移植

**根因**（本轮定位到三个真问题）：

1. `autoShelf` 读的是 `listing.skus/attributes`，而它们**只有点过「保存」才写**，
   所以日志里出现「SKU：草稿里没有规格，跳过」——用户明明在工作台里编辑了 10 条规格；
2. 驱动只填标题就提交，属性 / SKU / 图片 / 详情 / 物流全空，必填项一大堆；
3. `submitScript` 在**页面里 await 90 秒**等回执，表单提交会销毁执行上下文，
   所以永远等到「提交后 90 秒未收到入仓回执」。

**改了什么**

| 位置 | 改动 |
| --- | --- |
| `selectionpool/service.js` | 上架改读**本机草稿**（`editorStore.get`），标题/类目/参数/规格/详情图全按草稿；价格规则套到草稿规格上并写日志「同行价 × N 减 M 元，改 K 条规格」 |
| `selectionpool/driver-v2.js`（重写为 v3） | 按老软件顺序逐段填：品牌 → 标题（组件+DOM 双写回读）→ 属性（含**必填缺口扫描**）→ SKU（价格/库存/商家编码 + 缺口）→ **必填兜底** → 物流（发货地/提取方式）→ 图片（下载到临时目录后走 CDP `DOM.setFileInputFiles` 上传 1:1 主图，读 `slotImages` 的最终图位，本机图直接用路径）→ 详情图 → 提交（勾「放入仓库」）→ **主进程轮询回执** |
| `selectionpool/driver-v2.js` | 新增 `[fill-required]` 必填兜底：扫发布页上标 `*` 但空着的输入框，用「草稿参数 + 由参数推出的值」（产地→省份、净含量→总净含量、保质期、包装方式、是否进口、生产许可证编号/标准号/厂名/厂址/配料表）做确定性同义匹配填入，**不调 AI、不联网**；填不上的写进日志与失败原因 |
| `selectionpool/driver-v2.js` | 提交改为「页面里只点一下」+ 主进程每 1.8s 读一次 `location.href / 页面错误提示`，75 秒超时把窗口留给人；验证码立即停止并留窗 |

**怎么验**：选一件有草稿的商品上架 → 日志依次出现
`按本机保存的草稿上架` / `上架价格` / `打开发布页` / `发布页就绪` / `[fill-title]` / `[fill-attrs]` /
`[fill-sku]` / `[fill-required]` / `[fill-logistics]` / `[fill-images]` / `[fill-detail]` / `[submit]`。

**仍要你确认的**：详情图正式环境要走「图片空间接口」（老软件 `[fill-detail] 详情图已上传到本店图片空间 16 张（接口上传）`），
本轮走发布页文件上传入口；图片空间接口需要 `taobao.picture.upload`（或服务市场等价接口）凭证后才接。

## 连带修的 4 个缺陷

| # | 缺陷 | 改动 |
| --- | --- | --- |
| A | 队列里「未执行」的品永远挂在排队中 | 队列结束时把 `queued` 标成 `stopped` 并写一行日志 |
| B | 队列弹窗每 2.5s 整块重绘，输入框被抢焦点 | 有输入框聚焦时跳过重绘，重绘前后保持日志滚动位置 |
| C | 店铺分类下拉选完不保存 | 新增 `dlg-shelf-shopcat` 分支 + 回显已保存分类 |
| D | `local:` 本机图片被 `SKU_IMAGE_SOURCE` 挡掉 | 正则支持 `local:<绝对路径>` |

1. `chrome://extensions`（或 360 扩展管理页）→ 重新加载 **AI作图插件 0.6.19**（或用 `AI作图插件-0.6.19.zip` 装）→ 刷新已打开的商品页；
