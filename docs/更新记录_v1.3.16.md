## 1. 上架卡住不动

**现场**：日志最后一行是 `[fill-images] 透明素材图：素材器步骤 上传=1 勾选=1`，
之后 13 分钟没有任何新行，进度条停在 0%，停止也停不下来。

**成因（代码级确定）**：勾选完成后紧接着要回读图位（`read()`）、量素材中心 iframe 位置
（`MEDIA_BOX_SCRIPT`）、读弹层是否还在（`MEDIA_PRESENT_SCRIPT`）—— 这些调用都是
`win.webContents.executeJavaScript(...)`，**没有超时**。发布页一旦被平台的 `alert/confirm`
（素材中心「图片已被使用 / 尺寸不符，是否继续」这类）阻塞渲染进程，这些 promise 永远不返回，
整件商品就无限期挂在那里；日志自然也停住。

**修法**：

1. 发布窗口建立时就给主框架、已有子框架、后续新建的每个 iframe 注入
   `PAGE_DIALOG_GUARD_SCRIPT`：把 `alert / confirm / prompt` 换成「自动确认 + 记录文本」。
   弹窗不再阻塞渲染进程；被自动确认的内容由 `drainPageDialogs()` 写进执行日志
   （`[dialog] 平台弹窗「…」已自动确认`），不再悄悄消失。
2. 新增 `evalJs(win, script, timeoutMs)`：每次页面脚本都有上限，超时按本步失败处理并记一行
   `[guard] 页面脚本 N 秒没有响应（平台弹窗或页面卡住）`。素材中心整条链
   （回读 / 点图 / 确定 / 关弹层 / 透明素材图核验 / 批量导入弹窗）全部改用它。
3. 素材器「勾选完成 → 回填图位」每一轮都写日志（第几轮、回读几张、页面是否无响应），
   卡在哪一步一眼能看出来。
4. 服务端每个商品都有步骤标记：`step('上传透明素材图')` 等 20 个节点，
   日志里会出现 `[step] …`，最后卡住的步骤可直接报给排查。
5. 服务端看门狗：
   - 每 40 秒一行心跳：`⏱ 已运行 X 分 Y 秒 · 当前步骤：…`（心跳不刷新「有新进展」时间）；
   - 连续 **180 秒**没有任何新日志，或单件超过 **25 分钟**，判定卡住 → 自动中断这件商品，
     日志写明「上架卡住：连续 N 秒没有新进展（最后步骤：…）」，队列继续跑下一件；
   - 卡住会以 `PUBLISH_STALL` 记一条失败记录（「失败排查」里可查），但不登记人工补全任务；
     手动停止不计失败、不写失败记录。

## 2. 正在上架的产品停不下来

**成因（代码级确定）**：`queueStop` 只把 `stopRequested` 写进队列文件，执行循环要等
`driver.publish()` 自己跑完才会看到这个标记。页面卡住时 publish 不返回，所以永远停不下来；
进程重启后队列文件里还可能残留 `running: true`，界面就一直停在「正在停止…」。

**修法**：

1. `driver.cancel(reason)`：置停止标记并**立即销毁发布窗口**，挂在页面上的
   `executeJavaScript` 当场失败，当前商品立断；导出 `currentStep()` 供日志/看门狗使用。
2. 服务端每个批次持有 `abort`，`driver.publish()` 与「停止信号」`Promise.race`：
   点停止 300ms 内队列就收尾（实测 273ms），当前商品标为 `stopped / STOPPED`，
   不再算失败；未开始的排队商品标 `stopped`，`stopRequested` 一并清掉。
3. `publication.recoverStopped()`：没有执行中的 runner 时（上次异常退出 / 重启遗留），
   点停止会把 `running` 与残留的 `running/queued` 商品一次性收干净，界面不再卡在「正在停止…」。
4. 界面：按钮文案「停止上架」，提示改写为「已停止上架：当前商品已中断，排队商品不再执行」。

## 3. 店铺分类 = 发布页的「店铺中分类」

**现场**：设置页原来列出的是平台类目树（`categorySelectChildren`，一级/二级/叶子类目），
和用户指的「店铺中分类」（卖家自己建的分类：爆单品 / 心想事成 / 多金多金 → 多金T、多金Q…）不是一回事。

**修法**：

1. 新增 `selectionpool.shopCategories`（`src/selectionpool/category.js`）：
   用店铺自己的登录态开隐藏窗口读**商品发布页**的「店铺中分类」下拉，
   只打开下拉、读选项、按 Escape 关掉，不选、不提交；按店铺缓存 7 天
   （`selectionpool/shop-categories.json`）。上架成功后把本次页面读到的完整选项回写缓存。
2. 页面脚本（`driver-v2.js`）：定位「店铺中分类/店铺分类」标签 → 找到同一行的「选择分类」控件 →
   打开下拉 → 读分组标题与带复选框的分类名 → 关下拉。
3. 上架时 `fillShopCategory()`：按保存的分类名勾选（支持多选），合成点击打不开下拉就用
   CDP 真实鼠标点字段坐标再勾；最后回读，没勾上只告警并列出下拉可见项，不拦提交（选填）。
4. 设置页 UI：每家店铺一个「选择分类」按钮，展开后是分组 + 复选框（可多选），
   显示已选数量与名字，可「清空本店分类」；「刷新」才开窗口读发布页，
   打开弹窗只读缓存，不会每开一次就开一个隐藏窗口。
5. 配置字段：新增 `shopCategoryNames`（profileId → 名称数组）。旧 `shopCategoryIds`
   是平台类目 ID，语义不对，保留字段但不再使用、不再展示。

## 10. 店铺中分类取成了日期（读错列）

**现场**：设置页列出来的是 `2026-06-02 / 2025-07-14 / …`，不是「爆单品 / 好运连连 / 多金多金 → 多金T…」。

**成因（代码级确定）**：宝贝分类页的表格不止一列（前面还有复选框、创建时间），
上一版用「每行第一个非空单元格」当分类名，正好取到了**创建时间**列；树形箭头 `▶` 也被当成名字。

**修法**（`category.js` 的 `shopCategorySiteScript`）：
1. 先找表头里文字是「分类名称 / 宝贝分类」的那一列，只读这一列（下标来自表头，不再猜第一格）；
2. 名称优先读单元格里的 `input.value`（截图里分类名就是个输入框）；
3. 过滤日期/时间/纯符号（`2026-06-02`、`12:30`、`▶` 等一律不要）；
4. 子分类：按名称控件的左坐标算缩进层级（子分类比父分类更靠右），父名写进 `group`，
   设置页按「多金多金 / 多金T」分组展示，子分类都能选；
5. 跳过带 `<th>` 的表头行与「添加子分类」按钮；
6. 缓存版本升到 v2（旧的日期缓存直接作废，下次刷新不会又显示日期）。

**验证**：用 jsdom 构造与截图一致的表（复选框 / 创建时间 / 分类名称 input / 编辑删除 / 子分类缩进），
跑真实页面脚本：得到 `爆单品、好运连连、心想事成、今天也要开心哦!、多金多金、多金多金/多金T/Q/L、财多财多、爆多多`，
无日期、子分类分组正确。

## 11. 执行日志：滚轮能翻、不被拉回顶部

- **滚轮翻不动的原因**：编辑器安装的「弹窗滚轮护栏」把可滚动元素限定在 `.spx-body` 等，
  日志区 `.spx-log` 不在名单里 → 鼠标在日志上滚动被当成「弹窗空白处」`preventDefault()` 吃掉。
  已把 `.spx-log,[data-spx-log]` 排到 `.spx-body` 之前（`closest` 取最近祖先），
  并给日志加 `overscroll-behavior: contain`、加大高度（300px）、加粗滚动条。
- **不再自动跳回顶部**：整页重绘会换掉 DOM → 滚动条归零。现在：
  - 重绘前后记录/恢复「是否在底部 + 具体位置」；
  - 另挂 MutationObserver，日志节点一换就立刻恢复（浏览器绘制前，肉眼看不出跳动）；
  - 在底部时新日志自动跟到最新；用户自己往上翻（滚轮/拖滚动条）后就不再拉回；
  - 打开进度弹窗时默认停在最新一行。

## 12. 透明素材图卡在素材中心

**现场**：`素材中心已上传 1/1 → 素材器步骤 上传=1 勾选=1 → 第 1 轮回读时页面没有响应`，
之后连续 181 秒无进展，被看门狗中断。

**成因**：透明素材图的回填步骤会**点素材卡片图片**，这一下会让平台发布页整页无响应
（`executeJavaScript` 全部超时）；后续「素材地址直写」也在这张卡死的页面上，自然全失败。

**修法**：
1. 透明素材图改成 `skipCardClick`：上传拿到本店素材地址后**不再点卡片**，
   直接回读 → 写素材地址 → 核验；只点「帧内/父页确定」，不点图片；
2. 回读连续 2 次无响应就立刻收摊（`page-no-response`），交给地址直写/选择器兜底，不再耗 4 轮；
3. 每个图片组开跑前先 ping 页面（`1+1`，3 秒），连续两次不通就抛 `PAGE_HUNG`：
   这件商品快速失败（约 50 秒内），不拖整批；窗口直接销毁，不留一个点不动的页面；
4. `leaveWindowForManual` 里的脚本也加了 6 秒超时（页面卡死时它以前也会挂住）；
5. 失败码 `PAGE_HUNG` 摘要：「平台页面无响应，已自动中断（可直接重新上架）」。

**验证**：驱动脚本编译通过；停止/模板/日期等既有用例回归通过。
真实平台仍无法在本机复现点击卡片导致卡死，需现场再跑一次确认。
