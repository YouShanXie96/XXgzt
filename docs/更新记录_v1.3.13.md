## 1. 系统「打开」窗口弹到桌面 —— 全局拦截

**原因**：`Page.setInterceptFileChooserDialog` 只对发出它的 CDP session 有效。素材中心的 `<input type=file>` 在跨域 iframe（OOPIF）里，chooser 事件走 iframe 自己的 session；之前在主 session 上临时开一下、点完就关，拦不住 iframe 的 chooser，于是 Windows 原生「打开」框直接弹出来。

**修法**：发布窗口创建时（`loadURL` 之前）就 `debugger.attach('1.3')` + `Target.setAutoAttach({flatten:true})`，对主 session 和每个 `Target.attachedToTarget` 的 session 全部开拦截并监听 `Page.fileChooserOpened`；chooser 全部进 `fileChooserGuard.choosers` 队列，上传时用它自己的 `sessionId` + `backendNodeId` 回喂文件。**全程不再有局部 `setInterceptFileChooserDialog(false)`**；三个旧路径（`uploadMainViaChooser` / `uploadMainViaSucai` / `uploadViaChooserAt`）全部改为从 guard 取 chooser。窗口结束时 dispose。

## 2. 样品 —— 只认 radio，删掉所有模型写入

- `fillSampleItemScript` 重写：不写 `formValues`、不写 component、不读 `getComponentValue`；只返回"正装"radio 的 CDP 点击坐标，判定只用 `input.checked` / `aria-checked`。
- `xhSampleRead` 同步改为只看 radio（删掉模型交叉校验那 40 行）。
- 主流程和预提交复核都用真实鼠标最多点 3 次「正装」，每次回读 checked，直到一致；点不中明确报错、不带着样品提交。
- 日志不再出现误导性的「组件 sampleItem=正装」。

## 3. 素材中心上传 —— 补老软件的两处关键环节

- 逐张上传时每次都跑老软件的 `UPLOAD_CHALLENGE_STATE_SCRIPT`（滑块/限流检测）：平台要求验证时立即停并明确报错，不再傻等再把失败伪装成成功。
- 补充逐步日志：`素材器步骤 上传=N 勾选=M`、`点帧内确定…`、`点父页确定…`，下次日志能直接看出卡在哪一步。

## 4. 提交 —— 照搬老软件 `submitToWarehouse`

- 提交前跑 `confirmWarehouseRadioScript`：确认「放入仓库」radio 真 checked（含 class/aria/`:checked`），不是就**停止提交**（避免提交到"直接上架"流程，那样永远等不到 `auctionStatus=-5`）。
- 提交后每秒读一次错误，**连续两次相同的校验错误就停**并报出具体字段，不再白等 60 秒。
- 超时/停下时，在关弹窗**之前**跑 `submitStallDiagScript`（老软件 `SUBMIT_STALL_DIAG_SCRIPT` 同款）抓可见弹窗/toast 文字 + 提交按钮状态，写进日志和失败原因——以后不会再出现"只有一句无回执、现场被自己关掉"。
- 回执判定严格化：`success.htm` + `auctionStatus=-5` + `isSuccess=true` + `isEdit!==true` + 合法 itemId（老软件 `warehouseReceipt`）。

## 5. 详情图 —— 先传本店素材中心，再源码导入（用户追加问题）

**老软件做法**（`fillDetailImages` → `fillDetailImagesViaImport` → `uploadDetailLocalsViaWindow` → `importDetailUrls`）：
采集的详情图 URL（别人的图）**不能直接写进详情**，而是：
1. `downloadPublishLocals` 把每张图下载到本地临时文件；
2. 分批 ≤20 张，走 `batchUploadSelectInSucai({uploadOnly:true})` 上传到**本店素材中心**；
3. `buildReadNamedAssetsScript` 按文件名从素材卡读回**本店图片空间 URL**；
4. 把这些本店 URL 用「源码导入」写进详情，读回逐张核对顺序。

**我们之前**：`buildFillDetailSourceScript(imagePlan.detail)` 直接把采集的别人 URL 写进源码，等于详情里全是外链/防盗链图，随时被平台判无效——这正是你怀疑的问题。

**现在**：`uploadDetailImages()` 按老软件同款实现（下载 → 分批上传素材中心 → 按文件名读回本店 URL → 限流检测），只有全部拿到本店地址才源码导入；失败则明确报"不写采集外链，请手动补详情图"，不再伪造成功。

## v1.3.14 紧急修复：上架卡在「打开发布页」、进度 0/1、日志不动（2026-11-18 11:13 现场）

**原因（确定，不是猜）**：v1.3.13 插入的 `fileChooserGuard.install()` 位于 `loadURL` 之前，
里面 `Target.setAutoAttach` / `Target.getTargets` / 逐个 `Target.attachToTarget` 三个 CDP 调用
**都没有超时**。任何一个不返回，整条链就永久挂住：窗口建了但页面没加载，
日志最后一行停在「打开发布页 catId=… 直达 fastpath」，进度 0/1。

**修法**：
- 每个 CDP 调用单独 0.9–1.2 秒超时，整个 install 最多 3 秒；
- install 失败/超时也照常 `loadURL`——拦截装不上只是退化成"没有 chooser 守卫"，绝不阻塞上架；
- 新增两条日志：`[open] 文件选择框拦截已就绪，开始加载发布页`、加载期间每 6 秒一条心跳
  （表单项/输入框/ready），以后再慢也不会看起来"日志不动"。
