## 1. 「是否为样品」日志说正装、页面还是样品

### 老软件怎么做的（实证）

老软件里根本没有「点正装单选框」这段代码——`dist/main` 全量搜索 `正装` 只命中 `form-capture-harvest.js`
的一处**只读**映射（`mapSampleItem`：0=正装 / 1=样品）。它是把「是否为样品」当**普通类目属性**写的：

`form-capture-publish-scripts.js:buildFillAttrsScript`

1. 从 `window.Json.models[keyProp|itemProp|bindProp].dataSource` 里按 `label` 找到这一条（`name` 形如 `p-147956252`）；
2. 取该属性的选项 `{value,text}`，命中文案 `正装` 的那一项；
3. `formValues[store][name] = {value, text}` → `engine.updateModels({formValues})`；
4. `getComponentValue(store)[name]` 回读。

老软件抓下来的记录里就是这样（`itemProp:{…是否为样品:"正装"…}`）。

### 新软件为什么一直失败

之前写的是 `formValues.sampleItem = {value:0,text:'正装'}` —— **组件名不是数据键**，平台直接忽略；
回读又读的是自己刚写进去的那个假键，于是「回读一致」。DOM 那次点击只改了画面，
之后任何一次重绘（提交校验、写图片/SKU 模型）都会按真实模型把选中态退回「样品」，
所以日志写「正装已回读」、截图是「样品」，提交也被拦。

另外 `preSubmitCheckScript` 里旧的 `sampleState()` 取容器内**第一颗** radio 判断选中，
容器同时包住「样品/正装」两项时必然误判 —— 这也是自检「正装已选」的来源。

### 现在的做法

- `fillSampleItemScript()` 重写：动态解析 store/key/选项 → 写 `formValues[store][key]` →
  `updateModels` → `getComponentValue` 回读；DOM 点击退为辅助，最后再补写一次模型（防点击把值带回样品）。
  类目 schema 里没有这一条时，才退化为老组件名 `sampleItem`（只作为触发重绘，不据此判成功）。
- `xhSampleRead()`（`readSampleScript` / 预提交自检共用）改为**模型优先 + radio 真实选中态**双确认：
  `sampleOk = 模型是正装 && (radio 也是正装 || 页面根本没有可读的 radio)`。
- 预提交失败分支：模型补写 → 真鼠标点一次 → 再回读，日志会写清模型键值和页面值。

日志会变成：
```
[fill-extra] 是否为样品=正装（已回读（模型 itemProp.p-147956252=0 → 正装））
```

## 2. 上传图片时「选择图片」弹窗卡住 / 图片传不上去

### 老软件怎么做的（实证）

`form-capture-publish-core.js` + `form-capture-publish-images.js:fillMainImage`：

1. **跨域 iframe 用 Electron WebFrameMain 取**：`webContents.mainFrame.framesInSubtree` 按 iframe 的 `src`
   找到 `sucai-selector-ng`，直接 `frame.executeJavaScript(...)`（`waitSucaiFrame` / `evalInFrame`）。
   **不挂 CDP target** —— `Target.attachToTarget` 拿不到 session 时整条链就断。
2. **「本地上传」只用帧内合成 click**，绝不发可信鼠标事件：可信点击会弹原生文件选择框，
   发布窗在后台/离屏时框一出来整页就像卡死。文件用 `DataTransfer` 直接灌进帧里的 `input[type=file]`
   （`buildInjectFilesScript`），等价人工选文件，走 plupload 原生队列。
3. 逐张上传、逐张在 `[class*="UploadPanel_fileItem"]` 里按文件名确认成功，间隔 1.8s±0.4s，最后点「完成」。
4. 按文件名勾选卡片（`buildSelectNamedImageScript`），再用**父页 CDP 坐标**把可信点击转发进 iframe
   （`iframe 矩形 + 帧内元素矩形`，穿透 OOPIF）触发 realtime 回填；裁剪/底部「确定」都点。
5. 以父页图组回读张数增长为准；关弹层只用 Escape（软关/remove 会把刚回填的图撤掉）。

### 新软件为什么一直失败

旧实现走 `Target.getTargets` + `attachToTarget` 拿素材中心 iframe（经常拿不到 → `no-media-target`），
然后又用 CDP 可信鼠标去点「本地上传」——原生选择框一弹出来就「冻结」；
失败后弹层不关，整层盖住发布页，后面的图位、提交按钮全部点不到，
最终表现为「提交后 75 秒未收到入仓回执」。

### 现在的做法

`uploadMainViaSucai()` 按老软件链路重写：

- `findMediaFrame()` = `framesInSubtree` + `executeJavaScript`（带超时），不再依赖 CDP target；
- 帧内合成点击「本地上传」→ 等 `input[type=file]` → `DataTransfer` 逐张灌入 → 逐张确认；
- 「完成」回素材列表 → 按文件名勾选 → 先点图（realtime），不行再「帧内确定 → 父页确定」；
- 只认父页图组回读增长；失败**一定关弹层**（Escape 优先）；
- 主图上传顺序改为「素材中心 → 原生选择框 → 主文档上传框」，不再先白等 8 秒选择框。

## 3. 透明素材图：不再走「批量导入」

老软件这个图位同样走素材中心（`fillGuideWhiteBgImage` → `fillMainImage`，slot = `#struct-whiteBgImage`）。
新实现把 `uploadWhiteBg()` 的顺序调成：素材中心 → 原生选择框 → 本地上传框 → 整组串行 → 直接写
`guideImageGroup.whiteBgImage`，避免先点通用「上传图片」把「批量导入」弹窗勾出来。

## 4. 提交前关闭素材中心弹层

新增 ⑧.5：提交前若素材中心弹层还开着，先关掉（并把被回滚的主图用 DOM 桥接回引擎），
再进自检和提交——这是「提交后没回执」最直接的一条原因。
