# 更新记录 v1.0.6（2026-11-11 下午）

对应插件：**AI作图插件 0.6.12**

## 1. 3:4 主图 / 视频仍为 0

采集侧增强（`src/capture.mjs`）：

- `collectTallImages()` 新增 **window 全局对象扫描**（`__INITIAL_STATE__` / `__NEXT_DATA__` / `__PAGE_DATA__` 等前缀键，
  深度 ≤5、节点预算 400），键名命中 `34|vertical|tall|longImage|ratio` 时收 URL
- DOM 侧：3:4 图集常在被隐藏的页签里（`getBoundingClientRect()` 全 0），
  改为**隐藏元素用 `naturalWidth/naturalHeight` 判比例**；只有尺寸也拿不到时，才要求 URL 带 `750x1000 / 3_4` 标记
- `collectVideos()` 新增：`<video data-src/data-video/data-url>`、`og:video` meta、
  `mainVideoUrl`，以及只有 `videoId` 时按淘宝云视频规则拼候选直链

> 如果这两项**仍然**是 0，说明这个商品页确实没把 3:4/视频放进首屏数据里（要打开「图集/视频」页签才由
> `mtop.taobao.pcdetail` 返回）。下一步需要给插件加 MAIN world 响应钩子，把这支接口的原始响应截下来解析。

## 2. SKU 图显示 28 张（实际 14 张）

`skuImageSection` 把「草稿里的采集基线」和「采集详情里的 skuImages」拼在一起，同一批图算了两遍。
改成按 URL 去重后合并 → 14 张。

## 3. 价格为空 / 批量改价没反应

- 规格价采集不到（`price_fen` 全 null）时，**用商品采集价兜底**填到每条规格（老软件同样把商品价顶到规格上）。
- 有了基准价，`批量改价` 才能算出结果；原来 `改 0 条` 是因为每行都没有同行价。
- 采集到真实规格价时会优先用真实价，不用兜底。

## 4. 规格表表头与数据错位

表头原来 3 列 `1fr 92px 92px`，数据行 9 列（勾选/图/替换/星/规格名/价格/库存/编辑/删除），
所以「价格、库存」落在图片和按钮上面。改为同一套 9 列网格，表头用占位格对齐到规格名/价格/库存。

## 5. 类目显示不对（5 级 vs 3 级）

两处改动：

- **入库不再用空值覆盖**：`service.ingest` 里归一化失败时保留插件已采到的 `category_path` / `category_id`
- **拆分不按单个 `/`**：类目名本身带斜杠（`粮油调味/速食/干货/烘焙`），只按 `>` `›` `→` `|` `、` `,` `，`
  分层，所以「零食/坚果/特产 > 糖果零食 > 传统糖果」正确显示为 **3 级**，与老软件一致
  （插件 `background.js` 的 `toLevels` 同步改了）

## 6. 图片点不开大图

编辑器的点击委托只处理 `data-action="selectionpool:editor-*"` 的元素；
采集图条和 1:1 图位卡片上只有 `data-sped-zoom`、没有 `data-action`，点击被直接忽略。
现在给这些图补了 `data-action="selectionpool:editor-zoom"`：

- 1:1 / 3:4 图位卡片
- 所有「采集的…」图条（1:1 原图、3:4、SKU 图、详情图、素材图）
- 规格表每行的规格图（顺带加 `object-fit: cover`，32×32 不再被裁成色块）
