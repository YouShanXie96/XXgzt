## 一、需要接口的那几项（凭证到位即生效）

### 1. 图片空间上传 + 回填（`selectionpool/picture-space.js`，新增）

| 能力 | 接口 | 没凭证时 |
| --- | --- | --- |
| 详情图/主图上传到本店图片空间 | `taobao.picture.upload` | `configured:false`，上架时回落到发布页 file input，日志写「需要申请：taobao.picture.upload」 |
| 把图片空间里的图关联成商品主图 | `taobao.item.joint.img` | 跳过 |
| 把详情图写进商品描述 | `taobao.item.update`（desc） | 跳过 |
| 回读 `item_imgs` 做一致性校验 | `taobao.item.seller.get` | 跳过 |

- 单张 >3MB 时用 `nativeImage` 压到 1600px JPEG（图片空间硬限制），日志标注「已压缩」。
- 并发 2、逐张回报、失败不阻断其它；`picture_path` 为空时判定失败（不看 HTTP 200）。
- 新增 IPC：`selectionpool.pictureSpaceStatus`（接口配置面板与编辑器底部都用它）。

### 2. 回填驱动（`driver-v2.js` → `backfill()` 真正实现）

流程：图位最终图（`slotImages`）→ 图片空间 → `joint.img` 关联主图（第一张 `is_major`）
→ 详情图 → `item.update(desc)` 写入 → 素材图 → **回读 `item_imgs`** → 图位状态按回读结果落。

- **只信回读**：回读不到就不标 `filled`。
- 凭证没填时返回 `DRIVER_NOT_READY` 并列出要申请的 4 个接口，**不动**图位状态（不会把「待回填」误标成失败）。
- 编辑器底部按钮文案跟着变：`回填需要接口凭证（见下方提示）`，下面一行直接写缺哪几个接口。

### 3. 凭证清单（这就是你要申请的）

| 接口 | 用途 | 优先级 |
| --- | --- | --- |
| `taobao.picture.upload` | 上传图片到图片空间 | P0 |
| `taobao.item.joint.img` | 图片空间图 → 商品主图 | P0 |
| `taobao.item.update` | 写商品描述（详情图） | P0 |
| `taobao.item.seller.get` | 回读商品/图片做校验 | P0 |
| `taobao.item.sku.update` / `taobao.skus.quantity.update` | SKU 价格库存回写 | P1 |
| `taobao.item.img.upload` | 直接给商品传图（不走图片空间） | P1 |
| `taobao.itemcats.get` / `taobao.itemprops.get` / `taobao.itempropvalues.get` | 类目必填属性（只 AppKey） | P0 |
| `tmall.brandcat.control.get` | 类目/品牌授权校验 | P0 |

填法：上品库 → 接口配置 → AppKey / AppSecret / sessionKey。填完这几项，「回填」按钮立刻可用，无需重启。

## 二、不需要接口的项（这一轮做完，立即可用）

### 4. 必填提议 + 记忆（`selectionpool/required-suggest.js`，新增）

老软件把「模板与源参数覆盖不到的必填项」交给公司 AI；这里做**完全不联网**的确定性提议，优先级：

```
参数证据  >  标题/规格推算  >  类目默认  >  上次成功记忆
```

- 从「250g*5袋」这类文案推出 `净含量 / 单件净含量 / 总净含量 / 包装数量`；
- `产地 → 省份/城市`、`包装方式`（参数没有就从标题「袋装/盒装/散装」取，食品类默认袋装）、`是否进口`（默认国产）；
- 食品类目没给保质期时按类目默认 `12个月`；
- 生产许可证编号 / 产品标准号 / 厂名 / 厂址 / 配料表 / 储存方法 有就带上；
- **记忆**：上架成功后把「推出来的值」按 `品牌|品名` 记住（最多 500 个商品），下次同款直接复用。

上架日志会写：`必填提议 N 项（标题推算/类目默认）：净含量=250g、省份=内蒙古自治区…`，
`[fill-required] 必填兜底（参数/标题推算/类目默认）：补填 4 项…；仍缺 SKU品质分类`。

新增 IPC：`selectionpool.suggestionsPreview`（渲染层/自测可预览提议）。

### 5. 组件感知填充（`fillSmartScript`）

同一个「名值」，按发布页实际组件类型分别写，解决「保质期是日期选择器、产地是级联、包装方式是下拉/单选」这类填不进去的问题：

| 组件 | 写法 |
| --- | --- |
| `<select>` | 按选项文字选中 + 派发 change |
| 单选 / 多选（label/li/span） | 按文字点击；多值按 `、,，/` 拆开逐个点 |
| 日期（`input[type=date]` / date 组件） | 原生赋值并规范成 `YYYY-MM-DD` |
| 级联（`.next-cascader` / select 触发器） | 点开下拉 → 在菜单里按文字点选项 |
| 其它 | 回落成「label 旁边的输入框」 |

### 6. 系列 / SKU 搜索标题 / 多件优惠 / 收起填写助手

- `[fill-series]` 系列原生写入并回报是否命中；
- `[fill-sku] SKU搜索标题`：试 `SKU搜索标题 / 搜索标题 / SKU标题 / 规格标题 / 商品搜索词`；
- `[fill-sku] 多件优惠`：有「多件优惠」区块就设件数与折扣（`2 @ 9.5`），没有就写 `未命中（no-panel）`；
- `[collapse-assistant]` 提交前先收起填写助手面板（挡住提交按钮的常见原因）。

### 7. 上品记录「按员工」成功率（`publication.js` + 上品记录弹窗）

- 记每条上架尝试的 `operatorName / teamName`；
- `publicationReport` 增加 `byOperator`：员工 / 团队 / 尝试 / 成功 / 失败 / **成功率** / 主要失败原因 Top3；
- 弹窗新增第三个页签 **按员工**，成功率 <50% 标红、50–80% 标黄。

### 8. 规格名整理（`selectionpool/sku-match.js`，新增）

老软件 `sku-match-ai` 的确定性版：去掉 `【】()（）`、emoji、`包邮/现货/爆款/正品…` 这类营销词，
把 `1000克*1袋` 统一成 `1000g*1袋`，重名自动加「（规格N）」；价格库存不动。
提供 `matchToTemplate(sourceNames, templateNames)`（字二元组 + 词元重合度，低于 0.5 不硬对），供后续接模板/AI 用。

入口：商品图片工作台 → SKU 面板 → **清理规格名**（先弹前后对照，确认才写）。

IPC：`selectionpool.editorSkuMatch`（`action=preview|apply`）。

### 9. 插件：主图去噪 + 离线推送队列（0.6.20）

| 能力 | 做法 |
| --- | --- |
| 主图去噪（老插件同规则） | 阿里 URL 的 `!!<6位以上数字>` 是上传账号；保留图数最多的账号 + `-item_pic.` 官方图，剔掉混进来的装修图/活动图 |
| 离线推送队列 | 工作台没开时不再丢采集：整包进 `chrome.storage.local`（上限 200，同商品只留最新），每 2 分钟 + 浏览器启动/安装时自动补传；4xx 不再无限重试，网络错误留队列 |

采集反馈会显示：`已排队（上品库没打开）：3 条待补传，打开谢谢工作台后自动进来`。
