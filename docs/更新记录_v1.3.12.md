## 对照老软件“选品池”

### 是否为样品

- 老软件 `form-capture-harvest.js` 只把 `keep.sampleItem` 作为采集值映射：`0=正装 / 1=样品`。
- 老软件真正上架时，如果是页面类目属性，则走 `buildFillAttrsScript`：
  从 `itemProp/keyProp/bindProp` 找选项，写 `formValues[store][name] = {value,text}`，
  `engine.updateModels` 后再用 `getComponentValue(store)` 回读。
- 当前版本的问题是：页面仍显示“样品”时，只要 `sampleItem` 模型读出 `0`，
  或页面的自定义单选框没有被 `input[type=radio]` 命中，`xhSampleRead()` 就可能按模型单独放行。

### 透明素材图

- 老软件 `fillMainImages` 把本次 `800×800` 透明 PNG 与主图一起上传，按本次文件名读回素材；
  实际加载原图，验证 `naturalWidth/naturalHeight = 800×800`。
- 素材中心漏图时，老软件改走本店图片空间接口上传本次 PNG，再用返回的新 URL 写表单。
- 当前版本之前主要看“图片数量增加”；透明图位替换旧图时数量仍是 1，
  于是旧冻结图、旧组件值和本次上传没有建立一一对应关系。

## 本轮修复

1. “样品/正装”现在必须读到可见控件的真实选中态；模型和页面冲突时直接拦截，
   不再允许 `sampleItem=0` 单独把“样品”报成“正装”。
2. `fillSampleItemScript` 用可见“正装”控件的真实点击坐标，支持原生 radio、
   ARIA radio 和样式类 radio；点击后重新构造回读结果。
3. 提交前如果页面仍有“对应正装商品ID，必填项未填”或真实控件仍是样品，停止提交。
4. 透明素材图必须同时满足：
   - 页面图与 `guideImageGroup.whiteBgImage` 是同一 URL；
   - 实际像素为 `800×800`；
   - 不是空图位；
   - 页面没有“冻结/失效/图片像素必须”提示。
5. 透明素材替换旧图时，按 URL 变化判断本次上传，不再只按数量增加判断。
6. 素材中心上传 PNG 时使用 `image/png` MIME，不再把 PNG 伪装成 JPEG。
7. 删除“直接写主图 CDN 地址就当作透明素材上传成功”的假成功路径；
   素材中心漏图时只尝试图片空间接口上传本次 PNG，否则明确停在人工处理。
